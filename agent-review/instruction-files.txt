# Files that agents read as instructions or configuration.
#
# Before the harness starts, 'run-review' removes every file in the PR tree
# matching these patterns and restores the ones that exist at the PR's base
# commit, so a pull request cannot rewrite the rules it is reviewed by. Files
# the PR adds or changes are kept as data, as '<path>.txt', under
# '.agent-review-context/pr-instruction-files/', so the review still sees them.
#
# One pattern per line, matched AT ANY DEPTH: harnesses pick up instruction
# files in subdirectories too (opencode attaches a nested AGENTS.md to every
# file it reads in that directory). A pattern ending in '/' matches a
# directory and everything below it. Blank lines and lines starting with '#'
# are ignored. Each pattern becomes the git pathspec
# ':(glob,icase)**/<pattern>' (or ':(glob,icase)**/<pattern>**' for
# directories), so '*' does not cross '/' and case does not matter. A
# symlink or a gitlink where a directory pattern names a directory, or at a
# directory leading to a pattern with '/', is reset too (see
# docs/agent-review.md, invariant 6).
#
# This is the union over all harnesses: extend it when adding an adapter
# (see harnesses/README.md).

# The caller adds its own patterns ('instruction_files' input), and every
# file it lists in 'rule_files' (which the prompt tells the agent to follow)
# is reset as well, by construction. Files named in the caller's prompt
# addendum must be covered by one of these, or 'run-review' fails closed
# (tests/test-instruction-coverage.sh).
#
