# Harness adapters

Each subdirectory adapts one coding-agent harness to the agent review
pipeline (see `docs/agent-review.md`). All files here are
read from the reusable workflow's own commit (`job.workflow_sha`), never from
the pull request or the calling repository.

| File         | Contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `install.sh` | `install.sh <prefix>`. Runs in the secretless `prepare` job. Installs an **exact** version with integrity checks (npm: `npm ci` against a committed `package-lock.json`; binaries: release URL plus SHA-256) into `<prefix>`, and writes the version to `<prefix>/VERSION`. It must not execute any harness code (no install scripts, no `--version`): `prepare` runs on the host with sudo and a cache-capable token; `run.sh` checks the version inside the sandbox with `check_version` from `common.sh`. The prefix is unpacked to `/opt/agent-review/harness/<name>` (read-only) and must run from there without network access.                                                                                                                                                                                                                                                                                                                                                  |
| `run.sh`     | Runs inside the sandbox from the PR checkout, under `timeout`. Environment: `PROMPT_FILE`, `REPO_DIR`, `OUT_DIR`, `CONTEXT_DIR`, `MODEL`, `HARNESS_PREFIX`, `PR_NUMBER`, and AWF's `AWF_API_PROXY_OPENAI_URL`. Keeps its configuration in a scratch home under `$TMPDIR` (a directory in the workspace), built from environment variables only; disables auto-update, telemetry, sharing and remote model catalogues; runs headless and writes `$OUT_DIR/review.md`. Exit codes: 0 review written, 2 ran but no review, anything else a failure. **Return 2, not 0, when the harness exits 0 without a real answer** (a step cap, a stall detector or a tool-call-only last turn can all do that): `run-review` posts whatever `review.md` holds after exit 0. Harness output goes to files in `$OUT_DIR`, which are not collected; print diagnostics only through `diag` in `common.sh`, which prefixes every line so that the harness's output cannot be read as a workflow command. |
| `wire`       | One line: `openai-chat` or `none`. `openai-chat` passes the key to AWF as `OPENAI_API_KEY`; every harness uses AWF's OpenAI listener, `$AWF_API_PROXY_OPENAI_URL` (an origin): clients that append only `/chat/completions` (opencode, Pi) need `$AWF_API_PROXY_OPENAI_URL/v1`. There is no `anthropic-messages` wire: with `ANTHROPIC_API_KEY`, AWF v0.29.12 opens an Anthropic listener whose `POST /messages` is not counted by `maxTurns`, and its entrypoint fails under `filesystem.allowWrite`. An Anthropic-API client can use the OpenAI listener, which forwards `/v1/messages` with a Bearer token (CSCS accepts it).                                                                                                                                                                                                                                                                                                                                                       |
| `README.md`  | Pinned version, how to upgrade it, the paths it reads as instructions or configuration (add them to `../instruction-files.txt`), and any outbound calls it tries to make.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

The harness name must also be added to the harness allowlist in
`agent-review/lib/agent_review/authorize.py` (`KEYED_HARNESSES` or
`KEYLESS_HARNESSES`), as keyed (`wire` `openai-chat`: it runs in the
`review` job, with the caller's environment and key) or keyless (`wire`
`none`: the `review-keyless` job); both jobs check that the `wire` agrees.
Callers that offer it add it to their `workflow_dispatch` choice.

Recommended: `opencode` with `zai-org/GLM-5.3-Flash`, `pi` as the alternative.

`common.sh` holds the helpers the adapters share: the scratch `HOME`, `NO_PROXY` for loopback and the listeners, and bounded diagnostics.

| Harness               | Version | Wire          | Ignores the repository's configuration with | Own turn cap |
| --------------------- | ------- | ------------- | ------------------------------------------- | ------------ |
| [opencode](opencode/) | 2.2.7   | `openai-chat` | `OPENCODE_DISABLE_PROJECT_CONFIG=1`         | 35 steps     |
| [pi](pi/)             | 1.5.2   | `openai-chat` | `--no-approve --no-context-files`           | none         |

`stub` makes no model call and writes a fixed review with hostile content
(@mentions of a handle that is not a valid login, HTML comments imitating
the comment marker, other markup that renders as nothing, invisible
characters, and optional padding); it tests the pipeline without any secret.
